# 深圳证券交易所、中国证券登记结算有限责任公司深圳分公司关于做好公司债结算模式调整相关准备工作的补充通知

各会员单位、结算参与人及相关机构：

为完善深圳债券市场基础制度建设，深圳证券交易所（简称：“深交所”）和中国证券登记结算有限责任公司深圳分公司（简称：“中国结算深圳分公司”）已于2012年4月9日通过D-COM系统和www.chinaclear.cn网站发布《关于做好公司债结算模式调整相关准备工作的通知》（具体内容请见附件），现就债券结算模式改革补充若干事项如下：

**一、**中小企业私募债（简称：“私募债”）

私募债的结算模式和公司债协议交易的结算模式保持一致：债券结算模式改革业务启用前实行T＋1逐笔全额非担保交收，业务启用后实行T＋0逐笔全额非担保交收。相关数据接口约定均与综合协议交易平台公司债相同，具体可参见《关于做好公司债结算模式调整相关准备工作的通知》中SJSMX0.DBF、SJSJG.DBF等接口说明。

请各结算参与人及相关单位根据本通知于2012年6月上旬做好相关技术准备工作。

**二、**关于数据接口规范成交号码字段的说明

综合协议交易平台公司债/私募债调整为T＋0非担保交收制度后，清算明细库SJSMX0.DBF中的成交号码字段与综合回报库SJSZHHB.dbf中即时回报记录的成交号码字段保持一致，但与回报库SJSHB.dbf中15：30后回报记录的成交号码字段没有必然的逻辑关系。会员单位核对清算明细时，可以使用清算明细库SJSMX0.DBF中的委托序号/申请单号字段左起八位与相应委托记录在综合委托库SJSZHWT.dbf（或综合回报库SJSZHHB.dbf）中的合同序号字段的最后八位关联匹配。

若确需依据清算明细库SJSMX0.DBF中的成交号码字段核对清算明细的会员，可以使用清算明细库SJSMX0.DBF中的成交号码字段与相应协议交易成交回报记录在综合回报库SJSZHHB.dbf中的成交号码字段关联匹配。

对于未实施协议平台接口电子化的会员，建议尽快实施协议平台接口电子化技术改造。在改造完成之前，会员可通过综合协议交易终端及时下载新格式回报库SJSZHHB.dbf。

附件1：

关于做好公司债结算模式调整相关准备工作的通知

各结算参与人及相关单位：

为适应债券市场发展的需要，提高深市债券交易交收效率，深交所和中国结算深圳分公司拟调整现行公司债结算模式，现将相关准备工作通知如下：

**一、**公司债结算模式调整方案说明

目前深市集中竞价系统公司债实行T＋1DVP（T 日为交易日，下同）净额担保交收，综合协议交易平台公司债实行T＋1 逐笔全额非担保交收，拟作如下调整：

1、集中竞价系统公司债结算模式调整为与国债、企业债等债券相同，实现集中竞价系统债券结算模式的统一；

2、综合协议交易平台公司债调整为T＋0 逐笔全额非担保交收；

3、公司债的权益登记日和除权除息日，调整为与国债、企业债等债券一致。

4、中国结算深圳分公司将在每个交易日间通过清算明细数据接口（SJSMX0） 分三个不同的时间点向结算参与人发送综合协议交易平台公司债的清算明细数据。在当日清算交收完成后，本公司通过交收结果明细数据接口（SJSJG） 向结算参与人发送综合协议交易平台公司债的交收结果数据。

结算参与人应当及时划付资金，确保结算备付金账户在16：00 有足额应付资金用以完成当日交收。

**二、**数据接口规范调整

根据结算模式调整方案，《深圳证券交易所数据接口规范》（Ver4.60）拟作如下变动：

1. 资金清算库SJSQS

公司债的集中竞价交易的清算数据及综合协议交易平台交易的清算数据不再通过SJSQS 发送。SJSQS 的清算业务含义表调整如下：

《中国结算深圳分公司结算参与人数据接口规范》（Ver 1.3） 拟作如下变动：

2. 增加清算明细库SJSMX0

增加SJSMX0 接口，其结构与SJSMX1 和SJSMX2 相同，与后者数据内容不重复，本接口用于分三个不同的时间点向结算参与人发送公司债综合协议交易平台成交的明细清算数据，后一时间点清算数据包含前一时间点清算数据，供结算参与人办理公司债综合协议交易平台成交的非担保交收。

SJSMX0 接口中数据按成交的先后排序。每个时间点发送的SJSMX0 文件中最后一条记录为该时间点发送数据的结束标识，其MXSJLB（ 数据类别）字段为’PC’，MXQSLS（ 清算流水号）字段为‘1’，‘2’…，表示该时间点数据为当日第几次发送，最后时间点发送的数据中该记录的MXQSLS 为‘END’。SJSMX0 的结构及各字段的填写说明见附件。

在当日清算交收完成后，本公司通过SJSJG 接口向结算人参与人发送综合协议交易平台公司债的交收结果明细数据，其中JGJSBZ 为Y 则该笔成交交收成功，为N 则交收失败。仍保留通过SJSGF 接口的B9 业务类别下发公司债大宗交易的非担保交收失败数据，且各字段填写方式不变，只是若有B9 数据，将在T 日下发，而非T＋1 日下发。结算参与人在进行公司债综合协议交易平台成交的交收记账处理时，只能选择SJSJG 或SJSGF 其一作为数据来源。SJSJG 接口的结构见《中国结算深圳分公司结算参与人数据接口规范》（Ver 1.3），SJSGF 接口的结构见《深圳证券交易所数据接口规范》（Ver 4.60 ）。

请各结算参与人及相关单位根据本通知于2012 年6 月上旬做好相关技术准备工作。深交所和中国结算深圳分公司将择机组织联网测试，测试事宜另行通知。

（1）本库用于向结算参与人发送公司债综合协议交易平台成交的明细清算数据，数据明细至投资者的每一笔委托。结算参与人可根据自身需要，从多个角度对清算明细数据进行汇总和处理。

（2）MXJSZH （字段1：结算账户），是托管单元（字段7：MXXWDM）所属的结算账户。

（3）MXSJLX （字段3：数据类型），‘01’：清算明细，‘02’：通知类数据，‘PC’：批次标签数据。

（4）MXYWLB （字段4：业务类别），业务类别代码。每种业务类别的含义参见下文业务类别含义表。

（5）MXWTXH （字段9：委托序号/申请单号），业务申报时的委托序号或申请单编号，左对齐，右补空格。

（6）MXCJHM （字段10：成交号码），深交所对业务委托进行回报时生成的成交号码，对于其它渠道申报的业务委托，成交号码可能为空。

（7）MXQSLS （字段11：清算流水号），对数据类型为‘01’的记录，该字段为结算机构生成的清算流水号码，左对齐，右补空格；对数据类型为‘PC’的记录，该字段为当前数据为该日第几次发送的数据，从1 开始，最后时点发送的数据该字段为‘END ’。

（8）MXQSSL：（字段13：清算数量）正数表示结算参与人应收数量，负数表示结算参与人应付数量。

（9）MXXYJY ：（字段16：信用交易标识）‘1’融资，‘2’融券，‘ ’其他

（10）　MXPCBS（字段17：平仓标识），‘1’：开仓，‘2’：平仓，‘3’：强制平仓，‘’：其它。

（11）　MXZQLB（字段18：证券类别），请参见《深圳证券交易所数据接口规范》（ Ver 4.60）中证券类别含义表。

（12）　MXGFXZ（字段19：股份性质），结算公司保留字段。

（13）　MXJSFS（字段20：交收方式），表示该类业务的交收方式。‘Y’：担保净额DVP交收；‘N’：非担保交收；‘A’：担保净额非DVP交收；‘’．其它。

（14）　MXHBDH（字段21：货币代号），‘RMB’：人民币；‘HKD’：港币；‘USD’：美元。

（15）　MXQSBJ（字段22：清算本金），表示该笔业务委托的清算本金，不含税费。正数表示结算参与人应收金额，负数表示结算参与人应付金额。

（16）　MXYHS、MXJYF、 MXJGGF、 MXGHF、 MXJSF、 MXSXF（字段23～28）表示各类税费，正数表示结算参与人应收金额，负数表示结算参与人应付金额。
