# 国务院信息化工作办公室、国家税务总局、国家工商行政管理总局、国家质量监督检验检疫总局关于开展企业基础信息共享工作的通知

## 国务院信息化工作办公室、国家税务总局、国家工商行政管理总局、国家质量监督检验检疫总局关于开展企业基础信息共享工作的通知（国信办[2005]10号）

各省，自治区，直辖市人民政府，国务院各部委，各直属机构：

为充分发挥信息化建设的综合效益，加强市场监管，促进财税增收，提高公共服务水平，2002年以来，国信办，税务总局，工商总局，质检总局联合在北京，青岛，杭州，深圳和上海，浙江，沈阳，大连，济南，厦门，成都等省市分两批开展了企业基础信息共享试点工作。各试点省市通过工商，税务企业登记信息的实时交换，发现了大量在工商机关登记但未作税务登记或已注销工商登记仍然营业的行为，堵塞了监管漏洞，促进了财税增收；同时，较好地解决了有关部门交叉稽核问题，提高了监管工作效率和公共服务水平，取得了良好的经济效益和社会效益。为进一步推广此项工作，实现全国范围的企业基础信息共享，经国务院同意，现将有关事项通知如下：

**一、**工作目标和主要任务

工作目标是：发挥信息化建设的综合效益，实现企业基础信息交换与共享，建立以工商部门的企业信息为基础，以组织机构代码为唯一标识的完整，准确，动态的企业基础信息库，加强动态监管，优化办事流程，提高工商，国税，地税，质量技术监督等部门的市场监管能力和公共服务水平。

主要任务是：制定企业基础信息交换流程和共享指标体系；建设企业信息交换平台，实现工商，国税，地税，质量技术监督部门间企业基础信息实时交换（省级工商，国税，地税，质量技术监督等部门已完成数据集中处理的地区，原则上在省级建设）；建立企业基础信息库；建立企业基础信息共享和应用的长效机制。

**二、**工作原则

各地区开展本级企业基础信息共享工作应遵循以下原则：

（一）应用导向，资源整合。各地区要围绕市场监管，财税增收，优化服务等业务应用需求，充分利用已有的网络基础设施，应用系统，数据资源，结合本级公共信息交换平台建设，科学制定符合本地实际的实施方案。

（二）因地制宜，量力而行。各地区要根据本级财力状况和信息化基础条件，充分考虑技术实现的可靠性，实用性和可扩展性，适时开展企业基础信息共享工作。

（三）条块结合，协调推进。各地区在实现本级企业基础信息交换和共享的同时，应主动加强上下级间的沟通协调，充分满足上级业务数据汇聚和下级业务数据应用的要求，支持各级行业管理职能的落实和地方跨部门业务协调的实现。

（四）制度保障，稳定运行。各地区要根据本地实际，制定系统运行，使用，维护管理办法，确保企业基础信息交换平台的稳定运行。

**三、**有关要求

各地区，各有关部门要加强对企业基础信息共享工作的组织领导和协调，明确任务分工，认真组织实施，确保取得实效。

（一）各省，自治区，直辖市人民政府要充分认识开展企业基础信息共享工作的重要性，切实加强领导，根据本地实际，组织有关部门，确定本地区开展企业基础信息共享工作的范围和层级，确定企业基础信息交换平台的主体，并及时与国家有关部门沟通进展情况。

（二）各地区信息化，国税，地税，工商，质量技术监督等部门要在本地信息化领导小组的领导下，建立协调工作机制，把本项工作纳入电子政务规划，制定建设实施方案，精心组织实施。

（三）国信办，工商总局，税务总局，质检总局要加强指导，协调解决企业基础信息共享工作中出现的问题，并根据各地区工作进展情况，适时组织检查和评估。

全国企业基础信息共享实施要求

根据《国务院信息化工作办公室、国家税务总局、国家工商行政管理总局、国家质量监督检验检疫总局关 于开展企业基础信息交换试点的通知》(国信办[2002]62号)、《关于深化扩大企业基础信息共享和应用试点的 通知》(国信办 [2003]47号)、《国家税务总局、国家工商行政管理总局关于工商登记信息和税务登记信息交换 与共享问题的通知》(国税发[2003]81号)文件精神及要求，在总结两年多来北京、青岛、杭州、深圳第一批试 点城市及上海、浙江、沈阳、大连、济南、厦门、成都第二批试点城市(省)试点成功经验及成果的基础上，制 定《全国企业基础信息共享实施要求》，指导全国开展企业基础信息共享实施工作。

**一、**适用范围

本实施要求提出了企业基础信息交换与共享系统的交换信息内容、信息交换流程、总体框架、系统建设规 范和管理规程等方面的具体内容，是指导和规范地方开展企业基础信息交换与共享系统建设、实施的主要依据。

5、年检信息：企业注册号、企业名称、年检年度、年检情况

4、非正常户信息：组织机构代码、企业注册号、纳税人识别号、纳税人名称、非正常户认定日期、非正常 户解除日期

5、提请工商行政管理部门吊销营业执照信息：企业注册号、企业名称、提请吊销原因、提请吊销日期

6、行政处罚信息：组织机构代码、企业注册号、纳税人识别号、纳税人名称、违法违章手段、行政处罚结 果、行政处罚日期

**三、**信息交换流程

(一)数据汇总、比对流程

通过企业基础信息交换平台，将工商、国税、地税、质监等四部门的企业基础信息汇总到交换中心；以工 商部门的企业信息为基准，对汇总信息进行信息一致性比对，比对的结果经企业基础信息交换平台返回给四部 门及交换中心；交换中心将完整、一致的企业基础信息存储到企业基础信息库。

(二)新增企业流程

1、工商部门的新增企业注册开业登记信息经交换中心交换给质监部门。

2、质监部门赋组织机构代码，经交换中心把含组织机构代码的企业开业登记信息交换给国税和地税部门， 并将赋码信息交换给工商部门。

3、国税和地税部门分别增加税务登记信息，并经交换中心将税务登记信息交换给工商和质监部门。国税登 记信息交换给地税部门。地税登记信息交换给国税部门。同时，分别经交换中心将完整的企业基础信息存储到 企业基础信息库。

(三)变更、年检、注(吊)销企业流程

1、工商部门变更、年检、注销、吊销企业流程

工商部门将业务应用信息库中企业变更、年检、注销、吊销等信息经交换中心交换给国税、地税和质监部 门。同时，交换中心更新企业基础信息库中工商部门提供的企业变更、年检、注销、吊销等信息。

2、国税部门验换证、注销、处罚流程

国税部门将业务应用信息库中企业验换证、注销、处罚、无照经营企业等信息经交换中心交换给工商、地 税和质监部门。同时，交换中心更新企业基础信息库中国税部门提供的企业验换证、注销、处罚、无照经营企 业等信息。

3、地税部门验换证、注销、处罚流程

地税部门将业务应用信息库中企业验换证、注销、处罚、无照经营企业等信息经交换中心交换给工商、国 税和质监部门。同时，交换中心更新企业基础信息库中地税部门提供的企业验换证、注销、处罚、无照经营企 业等信息。

4、质监部门组织机构代码废置、变更流程

质监部门将组织机构代码废置、变更等信息经交换中心交换给工商、国税和地税部门。同时，交换中心更 新企业基础信息库中质监部门提供的组织机构代码废置、变更等信息。

**四、**系统总体框架

企业基础信息共享和应用系统总体框架：交换网络、交换前置机、前置交换信息库、信息交换系统、信息 交换桥接、企业基础信息库、管理与服务系统。

系统拓扑结构如下。(略)

系统总体框架如下。(略)

(一)交换网络：连接工商、国税、地税、质监、交换中心交换前置机的网络。

(二)交换前置机：由操作系统、前置交换信息库、信息交换通讯接口、信息交换桥接接口、前置交换安全 管理模块组成。

(三)前置交换信息库：工商、国税、地税、质监等四部门及交换中心之间共享信息双向交换的中转数据库 。包括部门对外发布的信息和从其他部门接收的信息。

(四)信息交换系统：实现不同部门前置交换信息库之间安全、可靠、稳定、高效的信息交换传递系统。

(五)信息交换桥接：由部门业务应用信息库到前置交换信息库之间的信息交换桥接接口，以完成两个信息 库之间的在线实时交换。

(六)企业基础信息库：是以工商部门的企业基础信息为基础，以组织机构代码为唯一标识，经在线实时交 换及信息比对后形成的企业基础信息数据库。

(七)管理与服务系统：由数据比对、企业基础信息库管理与维护、日志管理、用户及权限管理、数据备份 以及对整个交换运行情况的监控等部分组成。

**五、**系统建设规范

(一)地方同级工商、国税、地税、质监等四部门间通过企业基础信息交换平台进行在线实时信息交换，建 立符合中心交换管理要求的交换与共享模式。

(二)使用全国统一的组织机构代码作为企业基础信息的唯一标识。

(三)建立以工商部门的企业信息为基础、以全国统一的组织机构代码为唯一标识的企业基础信息库。

(四)工商、国税、地税、质监等四部门协助牵头单位开发业务应用信息库与前置交换信息库之间的信息交 换桥接，各自负责运行和管理信息交换桥接，实现在线实时信息交换。

(五)系统设计应具有前瞻性，采用开放、标准、可扩展的技术体系架构。企业基础信息交换与共享系统的 设计要符合工商、国税、地税、质监等四部门之间企业基础信息交换与共享的需要，能够满足将来更多部门之 间信息交换与共享扩展的需要，成为地方未来实现部门间信息交换与共享的公共信息交换平台的组成部分，避 免重复建设。

(六)信息交换网络与工商、国税、地税、质监等四部门内部业务网络之间不能直接连通，采用交换前置机 和信息交换桥接的连接方式实现信息交换。

(七)系统必须支持工商、国税、地税、质监等四部门之间不间断、稳定可靠的信息交换传递。

(八)信息交换须采用软件加密方式实现加密数据传输，不采用加密机方式。

(九)通过交换中心和部门交换前置机的交换日志审计管理信息交换过程。

(十)对各部门系统管理员进入交换系统具有访问权限控制的管理功能。

(十一)中心交换管理可以对系统运行进行全面监视、管理和配置，对信息交换流程进行定制和调整。

(十二)企业基础信息交换系统必须支持异构数据库之间数据交换和共享，支持主流关系型数据库，支持不 同操作系统之间信息交换应用的互联互通。

(十三)原则上采用经过企业基础信息共享和应用试点实践检验的、经授权的国内标准符合性检测机构认可 的、具有自主知识产权的、国产的软件产品。

(十四)根据各地实际情况，部门交换前置机可采用部门分布和中心集中两种部署模式。

(十五)企业基础信息库部署在交换中心。

(十六)暂时不具备在线实时交换条件的地方，也可通过计算机网络采用在线非实时方式实现；根据本地实 际需要，采用日交换或周交换，逐步实现企业基础信息在线实时交换。

(十七)开展企业基础信息交换与共享建设的地方同级四部门中，业务应用信息不在本级进行处理的部门， 要设立与集中处理业务应用信息的上级部门相对应的虚拟业务应用信息库，仅存放本级企业基础信息交换与共 享所需的业务应用信息。通过信息交换桥接，实现虚拟业务应用信息库与本级前置交换信息库间在线实时交换。

**六、**管理规程

(一)建设管理

1、确定地方同级工商、国税、地税、质监等四部门为本级企业基础信息交换的节点。

2、开展企业基础信息交换与共享建设的地方，要结合本地实际，参照试点的成功范例，制定切实可行的实 施方案，确保建设实施工作取得实效。地方开展企业基础信息交换与共享系统建设的实施方案，要分别逐级报 送上级主管部门。

3、同级工商、国税、地税、质监等四部门的历史数据要统一开展信息一致性比对工作。各部门的历史数据 统一由交换中心负责按照企业名称、企业注册号等相关指标进行信息一致性比对，比对结果返回各部门。比对 一致的企业基础信息存储到企业基础信息库；比对不一致的企业基础信息由各部门分别完成信息一致性处理后 ，由交换中心存储到企业基础信息库，逐步补充、更新，保证企业基础信息的准确性和完整性。

4、地方信息化领导小组根据本地实际确定本级企业基础信息交换与共享系统及企业基础信息库的建设主体 ，地方信息化主管部门承担建设协调工作，同级工商、国税、地税、质监等四部门要协助建设主体完成建设工 作。地方要结合本地实际和部门职能，明确交换中心的管理部门。按照本实施要求，相关部门共同对地方的建 设工作逐级进行验收，并将验收报告分别报送上级主管部门。

5、同级工商、国税、地税、质监等四部门负责管理部署在本部门的交换前置机、信息交换桥接、前置交换 信息库。交换中心负责管理企业基础信息库、企业基础信息交换平台及中心集中部署的交换前置机，监视各部 门分布部署的交换前置机运行状态。

(二)使用管理

1、工商、国税、地税、质监等四部门既是企业基础信息提供者，也是企业基础信息使用者。要按照确定的 共享信息内容和交换流程，按时保质提供交换与共享的信息。

2、工商、国税、地税、质监等四部门之间交换的企业基础信息仅限于各部门内部使用，不能对外发布。

3、同级工商、国税、地税、质监等四部门，在实现企业基础信息交换与共享的同时，要负责将企业基础信 息向没有开展交换与共享建设工作的下级单位或基层单位下传。

4、地方同级工商、国税、地税、质监四部门之间交换与共享的企业基础信息，各自逐级向上级机关传送、 汇聚。

**七、**实施步骤

(一)以《实施要求》规定的信息交换流程和共享信息内容为依据，结合本地实际情况，确定工商、国税、 地税、质监等四部门及交换中心之间的信息交换流程和共享指标体系。

(二)结合本地网络环境、信息交换系统以及工商、国税、地税、质监等四部门业务应用系统建设、运行和 使用等实际情况，制定具体的技术实施方案。

(三)充分利用地方现有的电子政务网络资源和信息交换系统，构筑连接工商、国税、地税、质监和交换中 心的交换网络及信息交换系统。

(四)建设企业基础信息交换与共享系统，按照确定的信息交换流程实现工商、国税、地税、质监等四部门 及交换中心之间企业基础信息的实时信息交换。

(五)由交换中心负责定期对四部门间交换的企业基础信息进行信息一致性比对，形成完整、准确的企业基 础信息库。

(六)各地要根据本地实际，制定系统运行、使用、维护管理办法，探索企业基础信息共享系统运行、管理 和使用的长效机制。

附录一：

概念及术语

(一)企业基础信息

工商、国税、地税、质监等四部门涉及到企业注册登记、变更、注(吊)销、年检、税务登记、组织机构代 码登记等业务内容的基础信息，具有跨部门共享需求的特征。

(二)企业基础信息交换平台

工商、国税、地税、质监等四部门之间进行企业基础信息交换的通讯、传输与管理系统。

(三)交换前置机

企业基础信息交换平台中与工商、国税、地税、质监、交换中心等五个节点进行信息交换连接的交换前置 服务器。

(四)中心集中模式

企业基础信息交换平台中工商、国税、地税、质监、交换中心的五台交换前置机全部或若干物理集中、统 一管理的模式。

(五)部门分布模式

企业基础信息交换平台中工商、国税、地税、质监的四台交换前置机全部或若干物理上分别部署、各自管 理的模式。

(六)信息交换桥接

工商、国税、地税、质监等四部门业务应用信息库与前置交换信息库之间信息安全交换的连接通道。

(七)企业基础信息库

存储、管理企业基础信息的数据库。

(八)前置交换信息库

工商、国税、地税、质监等四部门与企业基础信息交换平台之间共享信息双向交换的中转数据库。

(九)信息一致性比对

对工商、国税、地税、质监等四部门的企业基础信息进行准确性和一致性核对的过程。

共享数据元素目录

(一)数据元素表示规范

1、序号：数据元素的唯一标识，用三位数字标记；

2、名称：数据元素的中文名称；

3、拼音缩写：数据元素中文名称的汉语拼音缩写；

4、说明：数据元素的解释；

5、数据类型：数据元素取值的类型；

```
┌─────────┬────────────────────────┐

│　　数据类型　　　│　　　　　说明　　　　　　　　　　　　　　　　　│

├─────────┼────────────────────────┤

│　　字符型(String)│通过字符形式表达的值的类型。　　　　　　　　　　│

├─────────┼────────────────────────┤

│　　数值型(Number)│通过可计算的十进制形式表达的值的类型。　　　　　│

├─────────┼────────────────────────┤

│　　日期型(Date)　│通过CCYYMMDD的形式表达的值的类型，符合GB／T7408 │

└─────────┴────────────────────────┘
```

6、数据格式：数据元素值的表示格式。

```
┌──────────┬──────────────────────────────┐

│　　　字符　　　　　│　　　　　　　　　　　　　含义　　　　　　　　　　　　　　　│

├──────────┼──────────────────────────────┤

│　　C　　　　　│表示数据类型为字符型　　　　　　　　　　　　　　　　　　　　│

├──────────┼──────────────────────────────┤

│　　N　　　　　│表示数据类型为数值型　　　　　　　　　　　　　　　　　　　　│

├──────────┼──────────────────────────────┤

│　　D　　　　　│表示数据类型为日期型　　　　　　　　　　　　　　　　　　　　│

├──────────┼──────────────────────────────┤

│　　．．UL　　　　　│表示长度不定的文本　　　　　　　　　　　　　　　　　　　　　│

├──────────┼──────────────────────────────┤

│　　．．　　　　　　│从最小长度到最大长度，前面附加最小长度，后面附加最大长度(也 │

│　　　　　　　　　　│可以只附加最大长度)。如C．．6表示最多6个字符；N2．．7表示最 │

│　　　　　　　　　　│少2位数字最多7位数字　　　　　　　　　　　　　　　　　　　　│

├──────────┼──────────────────────────────┤

│　　N．．p，q　│表示数据类型为数值型，最长p位，小数点后q位(小数点前为p—q　 │

│(p、q均是一个自然数)│位)。如N．．8，2表示最多8位数字，小数点后2位　　　　　　　　│

└──────────┴──────────────────────────────┘
```

注：

(1)用C或N后直接加自然数的方式表示定长。如C6表示6个定长字符(一个汉字相当于两个字符)；N4表示4位 定长数字。

(2)用D后加4、6、8，分别表示不同数据格式的日期型数据元素。D4表示CCYY；D6表示 CCYYMM；D8表示 CCYYMMDD。

7、来源：产生数据元素的职能部门名称；

8、注释：与该数据元素相关的其它说明，包括数据元素的取值范围、遵循的标准规范要求等。
